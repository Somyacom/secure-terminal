# Безопасность: модель угроз и review
## Часть 1. Модель угроз

### Что защищаем
Два канала: «терминал - сервер» (события пользователя) и «сервер - терминал» (ответы, по которым терминал что-то показывает или делает).

### Нарушители вероятные 

| Нарушитель | Возможности |
|---|---|
| Внешний в сети | Читает, перехватывает, изменяет, повторяет трафик и шлёт свои запросы. Ключей не знает. |
| «Сохрани сейчас — расшифруй потом» | Записывает трафик сегодня, чтобы расшифровать его квантовым компьютером в будущем. |
| Чужой терминал | Владеет **своим** валидным ключом и пытается действовать от имени другого терминала или читать чужое. |
| Посредник после TLS | Видит трафик за балансировщиком, где TLS уже снят. |
| Скомпрометированный сервер | Знает всё, что хранит сервер. |
| Любой клиент API | Шлёт произвольные байты и огромные тела, пытается уронить сервис или вытянуть внутреннюю информацию. |

### Остаточные риски
- **Кража ключа с работающего терминала** вредоносным кодом. Защита: TPM/secure element и быстрый отзыв (`keytool.py revoke`).
- **Метаданные видны серверу и прокси.** Метод, путь, `key_id`, время и размер не шифруются телом; от сети их скрывает TLS 1.3.
- **Черновые стандарты.** Гибридный KEM в HPKE - черновик IETF, формат гибридной подписи упрощён (подробно в README).
- **Несколько хостов.** Общий SQLite работает для воркеров одного хоста; для нескольких серверов нужно общее хранилище.
- **Объёмный DDoS** на сетевом уровне закрывается средствами сети (allowlist адресов терминалов, провайдер)..
